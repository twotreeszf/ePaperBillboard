# Markdown 排版测试

本文用于检查阅读器已实现的 Markdown 特性。每一节先说明预期效果，再给出示例。普通段落首行缩进两个字，标题不缩进。

---

## 一、标题

下面六行依次是一到六级标题，都应显示为粗体、不缩进，行首的井号不显示。

# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题

下面三行不是标题，应按普通段落原样显示井号：

####### 七个井号不是标题
#井号后没有空格也不是标题
文字中间的 # 号保持原样。

## 二、粗体、斜体与粗斜体

这是**双星号粗体**，这是__双下划线粗体__，粗体每个字比正常宽一像素。

这是*单星号斜体*，这是_单下划线斜体_，斜体在行中结束后，后面的正体字应有一点间隔不挤在一起。

这是***三星号粗斜体***，这是___三下划线粗斜体___，还有**粗体里套*斜体*再回到粗体**。

## 三、按原文显示的标记

两侧都是空格的星号按原文显示：3 * 4 = 12，a * b * c。

词内的下划线按原文显示：snake_case_name、file_name_v2.txt。

反斜杠转义：\*不是斜体\*，\_也不是斜体\_，\# 不是标题，\\ 显示一个反斜杠。

只有开头没有结尾的标记：**这句没有闭合的粗体会一直粗到行尾

下一行恢复正常，说明行内样式不会跨行延续。

## 四、行内代码、删除线、链接与下划线

方括号后面没有圆括号的不是链接：[只是方括号]，按原文显示。

## 九、代码块

代码块使用小一号的 12px 字，行距为 12px 的 1.2 倍（14px），四周画虚线外框，框内上下留 6px、左右留 4px。围栏行不显示，里面的 Markdown 标记原样显示，没有首行缩进，也不做两端对齐。代码块跨页时，断开处不画横边，左右竖边画到页边。

```
# 这不是标题
**这不是粗体**，~~这不是删除线~~，[这不是链接](https://a.b)
- 这不是列表
> 这不是引用
---
```

行首的空格缩进保留，代码块内的空行也保留：

```c
#include <stdio.h>

int add(int a, int b) {
    if (a > 0) {
        return a + b;
    }
    return b;
}

int main(void) {
    printf("%d\n", add(1, 2));
    return 0;
}
```

## 十、跨页与长段落

***这一整段都是粗斜体，并且写得足够长，翻页时如果某一页从这一段的中间开始，新页面的第一行仍然应该是粗斜体，而不是变回正常字体。这一段继续写下去，增加长度，让它更有可能跨越页面边界。阅读器在页从行中开始时，会向前找到这一行的行首，重放行内标记来恢复样式。再写几句，确保足够长，至少能占满五六行的位置，这样在不同的翻页位置都有机会测到跨页的情况。***

<u>这一整段都带下划线，同样写得很长，用来测试跨页后下划线是否仍然连续。如果新页面从这一段中间开始，第一行仍应有下划线。再写一些文字让它更长，继续增加长度，直到足够跨越页面边界为止，这样不同的翻页位置都能测到。</u>

> 这一整段是引用，同样写得很长，用来测试跨页后斜体和缩进是否保持。如果新页面从这段引用中间开始，第一行仍然应该是斜体、缩进一个字。继续写下去，增加长度，再增加一些长度，让它尽量跨越页面边界。
